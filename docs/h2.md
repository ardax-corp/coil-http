# HTTP/2 (M5)

TLS **ALPN** is available on [coil-tls](https://github.com/ardax-corp/coil-tls) (`alpn: "h2"` on `ClientOpts` / `ServerOpts` passed to `tls::{client,server}::enable`).

Frame header encode/decode lives in `http::h2` (`encode_frame` / `decode_frame`, connection preface). Payload codecs cover SETTINGS (6-byte identifier/value pairs; ACK is empty), WINDOW_UPDATE (4-byte increment, zero rejected), and GOAWAY (last-stream-id + error code). `headers_frame` / `headers_from_frame` wrap HPACK from `http::hpack`. The static table is RFC 7541 Appendix A (61 entries). Decode accepts Huffman strings (H=1), literal with incremental indexing, never-indexed literals, and dynamic-table size updates. Encode still uses raw strings (H=0) and literal without indexing. Default dynamic table size is 4096 octets (`HpackTable::new` / `decode_header_block_with` for a shared table).

`H2Session` in `http::h2_session` is an in-memory server view of a client byte buffer. `feed` consumes the 24-byte connection preface, then frames via `decode_frame`. The first frame must be SETTINGS on stream 0; a non-ACK SETTINGS is answered with SETTINGS ACK (flag 0x1, empty payload) on `drain`. HEADERS on odd stream ids store decoded names/values; DATA on those streams accumulates until END_STREAM. Two streams can be interleaved in one buffer. DATA/HEADERS on stream 0 or even client stream ids are `BadResponse`. WINDOW_UPDATE is accepted (increment 0 still fails in the codec). One `HpackTable` (default 4096) lives on the session and on the live `h2_connect` / `h2_get_over_h2` decoder; later HEADERS can use dynamic indices from earlier blocks. `headers_from_frame` still builds a fresh table for one-off decode. PUSH_PROMISE is still later. CONTINUATION is not assembled.

Cleartext **prior knowledge** (RFC 7540 §3.4) is on the wire for a single GET. `h2_prior_knowledge_get` builds the client preface + empty SETTINGS + stream-1 HEADERS (`:method` GET, `:path`, `:scheme`, `:authority`) with END_HEADERS|END_STREAM. `h2_connect("http://…")` TCP-connects, writes that, then reads frames (`h2_read_frame` / `frame_wire_len`) until stream 1 ends; status comes from `:status` (default 200) and the body from DATA. `h2_connect("https://…")` enables TLS in place (`tls::client::enable(stream, host, new ClientOpts(...))` with ALPN `h2,http/1.1`) and reads the selected protocol via `tls::alpn_protocol`. Exact `h2` speaks HTTP/2; anything else (including empty) falls back to HTTP/1.1 on the same stream. Loopback and self-signed peers use `h2_connect_tls` with `verify: false`. `h2_serve_once` on a bound `http::server::Server` accepts one TCP connection, optionally `tls::server::enable(stream, new ServerOpts(...))` with ALPN `h2` when `Server.tls` was set, feeds bytes into `H2Session`, ACKs SETTINGS, and answers stream 1 with HEADERS `:status` 200 plus DATA `ok` and END_STREAM. `h2_serve` is that path and requires TLS. Socket loopbacks are `examples/h2_loopback.hy` (cleartext) and `examples/h2_tls_loopback.hy` (package enable with `ClientOpts`/`ServerOpts` across threads, ALPN `h2`, then GET). `coil test` cannot spawn threads.

## Roadmap

1. Client/server negotiate `h2` via ALPN (`h2_connect` / `h2_serve`, `tls::{client,server}::enable` with `ClientOpts` / `ServerOpts`)
2. Shared framing layer in `src/http/h2.hy` (frame header, preface, SETTINGS / WINDOW_UPDATE / GOAWAY / HEADERS: done)
3. HPACK (`src/http/hpack.hy`: static table, Huffman decode, dynamic table; session table: done)
4. Multiplexed requests per TLS connection (`H2Session` in-memory: done; cleartext prior-knowledge GET: done; TLS ALPN GET: done)
5. Fallback to HTTP/1.1 when ALPN does not select `h2` (`h2_connect`: done)

See the [coil-http Linear project](https://linear.app/ardax/project/coil-http-e81f48ac1d8b) M5 milestone.
