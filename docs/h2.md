# HTTP/2 (M5)

TLS **ALPN** is available in coil-lang (`alpn: "h2"` on `io::net::tls::{client,server}::enable`).

Frame header encode/decode lives in `http::h2` (`encode_frame` / `decode_frame`, connection preface). Payload codecs cover SETTINGS (6-byte identifier/value pairs; ACK is empty), WINDOW_UPDATE (4-byte increment, zero rejected), and GOAWAY (last-stream-id + error code). `headers_frame` / `headers_from_frame` wrap static-table HPACK from `http::hpack`. The static table is a compact subset of Appendix A (at least `:method` GET/POST, `:path` `/`, `:scheme` https, `:status` 200, `content-type`, `content-length`).

`H2Session` in `http::h2_session` is an in-memory server view of a client byte buffer. `feed` consumes the 24-byte connection preface, then frames via `decode_frame`. The first frame must be SETTINGS on stream 0; a non-ACK SETTINGS is answered with SETTINGS ACK (flag 0x1, empty payload) on `drain`. HEADERS on odd stream ids store decoded names/values; DATA on those streams accumulates until END_STREAM. Two streams can be interleaved in one buffer. DATA/HEADERS on stream 0 or even client stream ids are `BadResponse`. WINDOW_UPDATE is accepted (increment 0 still fails in the codec). There is no TLS and no socket. `h2_connect` / `h2_serve` still return `HttpError::NotSupported`. Huffman, the dynamic table, and PUSH_PROMISE are still later.

## Roadmap

1. Client/server negotiate `h2` via ALPN
2. Shared framing layer in `src/http/h2.hy` (frame header, preface, SETTINGS / WINDOW_UPDATE / GOAWAY / HEADERS: done)
3. HPACK static table (`src/http/hpack.hy`: done)
4. Multiplexed requests per TLS connection (`H2Session` in-memory: done; wire/TLS still open)
5. Fallback to HTTP/1.1 when ALPN does not select `h2`

See the [coil-http Linear project](https://linear.app/ardax/project/coil-http-e81f48ac1d8b) M5 milestone.
